# F2 — XRI Hands Rig Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Quest-buildable Unity project with OpenXR, XR Interaction Toolkit and XR Hands, and a new `Room` scene (built from `Autism1`'s environment) containing a hands-only XR Origin and a poke button, verified by tests, an Android APK build, and Unity CLI screenshots.

**Architecture:** Package and settings changes are applied by idempotent `[CliCommand]` methods in `AutismVR.Editor` and pinned by EditMode tests, so every setting is reproducible headless. The `Room` scene is generated by a command that copies `Autism1`, strips its legacy objects, relights it and drops in XRI's hands rig; runtime behaviour lives in a new `AutismVR.Runtime` assembly with PlayMode tests. Verification uses XRI's XR Interaction Simulator in Play mode for Game-view screenshots.

**Tech Stack:** Unity 6000.6.0f1, URP 17.6.0, XR Interaction Toolkit 3.6.1, OpenXR Plugin 1.18.0, Unity OpenXR: Meta 2.6.1, AR Foundation 6.6.2, XR Hands 1.9.0, Input System 1.20.1, Unity CLI + `com.unity.pipeline`.

**Spec:** `docs/superpowers/specs/2026-10-21-autism-vr-rebuild-design.md` (§3 platform and interaction, §7 main scene, §8a device order); roadmap `docs/superpowers/plans/2026-10-21-autism-vr-roadmap.md` (F2 row).

## Global Constraints

- Devices: Meta Quest 2, Quest 3, Meta VR Glasses; **hands only** — every interaction must work with hands (and gaze on Glasses) and no controllers (spec §3).
- Unity 6.6 supports Meta VR Glasses through OpenXR with XRI and **XR Hands 1.9.0 or newer** (spec §3).
- Build: **IL2CPP, ARM64** only (spec §3). Graphics API: Vulkan only. Colour space: Linear.
- Android: **targetSdkVersion 34, minSdkVersion 32** (Meta Horizon requirement since 2026-03-01).
- Keep the `INTERNET` permission (GPT-Live in F6 needs it): never enable OpenXR "Force Remove Internet Permission".
- Main scene: build one new scene from `Assets/_Scenes/Autism1.unity`'s room with a fresh XRI rig; remove the other legacy scenes once the new scene works (spec §7).
- Project code under `Assets/_Project/` (Editor → `AutismVR.Editor`, runtime → `AutismVR.Runtime`, tests → `AutismVR.Tests.EditMode` / `AutismVR.Tests.PlayMode`).
- Commits: Udacity style (`type: Subject`, ≤50 chars, imperative, no period); **no Co-Authored-By trailer**. PR body: **no "Generated with Claude Code" line**.
- Screenshots: `docs/verification/f2-xri-hands-rig/*.png`. Project path `$P` = `/Volumes/DevDrive/Dev/Autism-VR`.
- Green = 0 compile errors; `unity test $P --mode EditMode` and `--mode PlayMode` exit 0; Android build exits 0; screenshots committed.

## Review Focus

1. **Active input handling left on the old Input Manager** → XRI 3 input actions silently do nothing and hands never select. Expected: Input System Package is the active handler. Pinned by `InputSystemIsActiveHandler` (Task 1).
2. **OpenXR enabled for Standalone but not Android** (or hand features off) → the APK launches with no hands. Expected: OpenXR loader on Android; Meta Quest Support, Hand Tracking Subsystem, Hand Interaction Profile and Eye Gaze Interaction Profile enabled on Android. Pinned by `XrBaselineTests` (Task 1).
3. **Legacy objects carried into `Room`** (missing scripts/prefabs from removed SDKs, old cameras, the `ViveCameraRig`) → errors on load and a second camera fighting the XR camera. Expected: `Room` has 0 missing scripts, 0 missing prefab instances, exactly one camera (the XR Origin's). Pinned by `RoomSceneTests` (Task 3).
4. **Poke button that only reacts to controllers / ray** → unusable with hands. Expected: the button is selected by a poke interactor. Pinned by `PokeButton_PokeSelect_RaisesPressed` (Task 4).
5. **Build settings still pointing at deleted scenes** → Android build fails. Expected: build scene list is exactly `Room`. Pinned by `BuildScenesAreExactlyRoom` (Task 3) and the Task 6 build.
